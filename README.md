Overview
This is a dictionary app that runs llm locally on your phone. It utilizes llama.cpp from github to make large language models run on cpu on phone. you can type in words or even sentences, and the model in your phone will start inference, locally, without ever the need to connect to the internet. since its an ai model, it has some randomcy.

Inspiration
Although the project is yet way behind finished and productable, the inspiration comes from whenever im hoping to find the meaning of some words or terms or phrases, i always rely on chatgpt. i specifcally opens a chat, paste the prompt that i stored and make that chatroom specifcally a dictionary. i can just enter words, phrase or short sentences, unlike traditional online dictionaries where phrases or idioms or short sentences are rarely accepted. i also like how the ai can be prompted to output with a very clean format, as well as i can decide the format in whatever framework i like just by adjusting the prompt. but the problem with using ai as dictionary is the memory is not very consistent which the formatting will gradually lost after certain length, and i cant go back to find some specific words or store them down in case i want to review what ive learnt. the length of the chatroom is also a problem. i have to open so much chatrooms since i searched so much words that the maximum length of the chatrooms are reached. thus i come up with the idea to write an app that works exactly like a dictionary, with high personilization and wide range of searching and translate function not limiting only common phrases and words. with the power of ai the dictionary could also be universal with any language you like. designing the app can also store the words you have searched for and keeping track of your learning etc.

the pivot is calling api while using the app definitely costs. so i come up with the idea where we just install an llm into your phone and boom thats just so perfect. however i overestimated the ability of small models with low parameters, as well as the inference speed of model relying on cpu of mobile phones. for instance, the infernce speed of a Q4 model with around 2.7B parameters is already very slow on phone, around 3 tokens/s, while the performance is way too poor compared to api. for even smaller models like 1B or less the instruction following ability is way too weak where it does serve as what you want. 

problem tackling
i tried using different methods to increase the inference speed of model on phone, including shortening the context window(not useful at all), cleaning the context window(cache) every time after the search was make since its just a dictionary where no history chat is needed for inference, use extremely quantized larger models like 2.6B Q2.

in order to improve the performance of the model, to let the models follow insturctions clearly, i tried prompt engineering(injecting system prompt) , however it showed poor prompt following ability with small models.  so then i added examples in system prompt to let the model follow. this hugely increases the cache and thus the inference speed becomes significantly slow again. then i pivot to train the model myself, finetuning the model using lora. i prepared around 200 example formats for the model to let it know its being a dictionary. the lora technique only involves of 1% of the model parameters or less, but yet the model stil overfit to the training data with not much example loops. if the model trains with less loops, then it fails to follow the preferred dictionary pattern, and if its trained to follow pattern it is being overfitted where the answers have much lower quality.
